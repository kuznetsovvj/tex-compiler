# tex-compiler
Веб-сервис для удаленной компиляции tex файлов с иллюстрациями asymptote

## Развертывание

Деплой автоматический: push в `main` запускает `.github/workflows/main.yml`, который по ssh
заходит на сервер, забирает изменения, пересобирает образ приложения и перезапускает контейнер.

### Базовый образ

`Dockerfile.app` начинается с `FROM texcompiler-base:latest`. Это TeX Live с Asymptote
поверх Ubuntu 22.04; сборка многогигабайтная, поэтому в деплое приложения она не
участвует. Образ обновляется workflow `.github/workflows/base-image.yml`:

- при изменении `Dockerfile.base` (push в `main`);
- раз в неделю по расписанию - TeX Live и системные пакеты регулярно получают
  обновления, слои закэшированы, пересборка занимает минуты;
- вручную (`workflow_dispatch`).

После пересборки образ сканируется Trivy (HIGH/CRITICAL с доступным фиксом -
workflow красный). Основа образа зафиксирована по digest в `Dockerfile.base`,
обновление Ubuntu - осознанная смена digest, а не плавающий тег. Приложение
пересборку базы не переживает: новая база подхватится при следующем деплое.

На новом сервере базу нужно собрать один раз до первого деплоя, иначе шаг
`docker build` приложения упадет с сообщением, что `texcompiler-base:latest`
не найден:

```bash
docker build -f Dockerfile.base -t texcompiler-base:latest .
```

### Что делает деплой

1. `git pull --ff-only origin main` - при локальных изменениях на сервере падает, а не создает 
merge-коммит;
2. `docker tag texcompiler-app:latest texcompiler-app:previous` - образ рабочей версии сохраняется для автоматического отката;
3. `docker build -f Dockerfile.app` - пересборка образа приложения;
4. остановка прежнего контейнера и запуск нового с `--restart unless-stopped`, поэтому после перезагрузки сервера сервис поднимается сам. Контейнеру дополнительно монтируются `docker.sock` и каталог рабочих областей задач (секрет `MOUNT_TASKS_DIR`) - см. раздел про изоляцию компиляции ниже;
5. проверка живости: до 30 секунд опрашивается `http://127.0.0.1:<PORT_OUTER>/`. Контейнер с `--restart unless-stopped` может числиться работающим, будучи в цикле перезапусков, поэтому смотрим именно HTTP-ответ, а не статус контейнера;
6. smoke-тест: через API компилируется минимальный тестовый документ, результат скачивается и проверяется на непустоту. Проверка живости видит только фронт и не замечает сломанный контур компиляции, а smoke идет тем же пайплайном, что и пользовательские файлы;
7. при провале любой проверки деплой автоматически поднимает `texcompiler-app:previous` и падает с ошибкой - см. раздел "Откат";
8. `docker image prune -f` - удаление висячих слоёв после успешных проверок. Тегированные образы, включая `texcompiler-base:latest` и `texcompiler-app:previous`, не затрагиваются.

### Изоляция компиляции

Каждый вызов `pdflatex`/`asy` выполняется приложением в одноразовом docker-контейнере
(`ContainerRunCommandBuilder`), а не в контексте самого приложения. У контейнера нет сети,
все capabilities сняты, включен `no-new-privileges`, rootfs только на чтение, запись
возможна только в `/tmp` (tmpfs с лимитом) и в примонтированный каталог задачи; процессы
идут от UID 1000 (совпадает с владельцем workspace на хосте, иначе pdflatex не смог бы
писать в рабочий каталог) с лимитами памяти/CPU/числа PID. Образ для контейнеров - тот же
`texcompiler-base:latest`.

Для этого app-контейнеру монтируются:

- `/var/run/docker.sock` - приложение вызывает `docker run`. В контейнер компиляции
  сокет не попадает. Сокет на хосте принадлежит `root:docker` (права 660), поэтому
  контейнер запускается с `--group-add <gid группы docker>` - workflow читает gid
  сам через `stat`. Без этого приложение под UID 1000 получило бы permission denied
  на сокете при первой же компиляции;
- каталог рабочих областей задач, общий с dockerd (секрет `MOUNT_TASKS_DIR`, значение
  вида `/var/lib/texcompiler-tasks:/tasks`). Приложению нужны оба пути: `WorkspaceRoot`
  (`/tasks`) - как каталог виден внутри контейнера приложения, и `WorkspaceHostRoot` -
  путь к тому же каталогу на хосте, потому что `docker run -v` резолвит источник
  на хосте. Workflow вычисляет `WorkspaceHostRoot` сам из секрета (часть до `:`)
  и передает приложению через переменную окружения. Контейнерный путь в `-v` не
  передавать: dockerd молча создаст пустой каталог на хосте, и pdflatex увидит
  пустой workspace. Приложение работает под UID 1000, поэтому на хосте один раз:
  `mkdir -p /var/lib/texcompiler-tasks && chown 1000:1000 /var/lib/texcompiler-tasks`.

Приложение работает не под root (UID 1000), поэтому все хостовые каталоги, смонтированные
внутрь для записи - storage, логи, каталог задач - должны принадлежать `1000:1000`:

```bash
sudo chown -R 1000:1000 <host-путь storage> <host-путь logs> /var/lib/texcompiler-tasks
```

Иначе первая же загрузка файла упадет с `UnauthorizedAccessException`, а раньше это
маскировалось тем, что приложение работало от root.

Локально и в CI, где docker недоступен, изоляцию можно выключить настройкой
`CompilationContainer:EnableIsolation=false` - тогда инструменты запускаются напрямую
(требуется локально установленный TeX Live с Asymptote).

### Секреты репозитория

`VDS_HOST`, `VDS_USER`, `VDS_SSH_KEY`, `PROJECT_PATH`, `MOUNT_STORAGE_DIR`, `MOUNT_LOGS_DIR`, `MOUNT_TASKS_DIR`, `PORT_OUTER`, `PORT_INNER`. Каталоги `storage` и `wwwroot/logs` монтируются томами с хоста и переживают пересоздание контейнера. Без заданного `MOUNT_TASKS_DIR` деплой падает на шаге запуска контейнера.

### Откат

Деплой перед пересборкой сохраняет рабочий образ как `texcompiler-app:previous`. Если
проверка живости или smoke-тест новой версии падают, workflow автоматически поднимает
`previous` и завершается с ошибкой - сервис недоступен секунды, а не часы, и не нужно
спешно чинить прод руками.

Ручной откат (если плохое поведение обнаружилось позже проверок) - вернуть образ
и закрепить состояние в git:

```bash
# на сервере: поднять предыдущий образ
docker stop texcompiler-app && docker rm texcompiler-app
docker tag texcompiler-app:previous texcompiler-app:latest
# дальше запуск как в workflow: run_app texcompiler-app:latest (флаги см. выше)

# в репозитории: откатить код, чтобы следующий деплой не вернул сломанную версию
git revert <хеш_коммита>
git push origin main
```
